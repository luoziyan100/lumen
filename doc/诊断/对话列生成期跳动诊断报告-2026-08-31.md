## 0. 一句话结论

跳动不是「整套前端 UI 要推倒」,也不是滚动状态机没写完。

**震源是助手气泡的提交语义:还在变的文本、和已经该定形的块,画在同一棵每个 delta 全量重解析的 Markdown 树上;重活(mermaid / 高亮 / 公式)以「占位 → 虚高 → 再裁」进滚动容器。滚动层(A)只是放大器。**

R11 把火力打在 A 上,P0/P2 已落地、P1(高度雪崩)未做。生成期仍跳,是因为 B/C 层高度根本不是单调增高——贴底跟得再乖也像在地震仪上调水平仪。

## 2. 第一性原理:跳动只有三种物理来源

视口里一块眼睛钉住的像素,不经手势就换位置,穷举只有:

| 代号 | 物理 | Lumen 里谁在干 |
|---|---|---|
| **A** | 程序改了 `scrollTop` | `useStickToBottom.scrollToBottom` / `restoreMsgAnchor` |
| **B** | 视口上方或内部的 DOM 高度变了 | 全量 Markdown 重解析、Mermaid 异步落图、过程卡 CurtainFold 收合 |
| **C** | 元素自身几何变了(viewBox / transform) | `MermaidBlock.tightenSvgInk`(按墨迹收虚高 viewBox,mermaid#1984) |

R11 的主因/放大项全部落在 A,外加「定稿瞬间高度突变」这一半截 B。本报告主张:**生成期主因是 B+C;A 在 sticky 时放大、在 manual 时用错了工具(消息顶锚点钉不住图内部墨迹)。**

层次图(因果从上到下,修要修最上层还在抖的那一层):

```
token / 工具步 / running 翻转
    → ChatTranscript 整列 map 重绘
        → react-markdown 对整篇累积字符串从头 parse     ← B 流式期
            → 未闭合围栏改写「前面已稳定块」的语义
            → 定稿后 Mermaid:占位 → ELK SVG → tighten    ← B+C
                → ResizeObserver 看见高度非单调
                    → sticky: followSettle 后拽到底       ← A 放大
                    → manual: 按「整条消息顶」回锚         ← A 用错对象
```

验收判据:若下层高度单调且一次落位,R11 已落地的 A 不应再造成「换来换去」。若下层仍非单调,改 A 无效——这解释了「滚动改了好几轮,生成时还是跳」。

## 4. 根因(按层,含证伪条件)

### 4.1 B-流式 — 整篇 Markdown 每个 delta 全量重解析

**机制**

- `ChatTranscript` 把 `it.content` 整串交给 `AssistantContent` → `Markdown` → `<ReactMarkdown>{children}</ReactMarkdown>`(`Markdown.tsx:86-94`)。
- 无按块切开、无「只修尾巴」。`deferMath` 只关掉 remark-math / rehype-katex / 把 mermaid 留在 `<pre>`(`Markdown.tsx:21-23, 48-49, 73-79`),**不阻止** GFM 对开围栏、列表、表格的全树重解释。
- 未闭合 ` ```mermaid ` 会把后续 token 吞进同一 code fence;闭合瞬间从「一块超长代码」裂成「图(仍是 pre,因 deferMath) + 后面的字」——结构跳。
- `rehype-highlight` 在流式期仍开着(`REHYPE_STREAM`),每个 delta 对整块代码重新高亮。

**为何造成「跳」而不只是「往下长」:** 重解析会改**已经画在视口里的前面几段**的盒(半截 `**`、列表、表格、围栏)。这是非单调、且发生在视口中部的 B,贴底/回锚都救不了「你正在看的那段字突然换成另一种排版」。

**证伪:** 一条无围栏、无列表、无表格的纯散文长输出,生成中若仍剧烈跳 → 本条不是主因,回到 A 或过程卡。

**证据:** V2(代码路径完整)。影响程度待 V1(§11 实验 1)。

### 4.2 B+C-定稿 — Mermaid 三次落位(R11 P1 的精确化)

**机制**( `MermaidBlock.tsx` )

1. `setPending(true); setSvg(null)` → 「正在绘制…」占位,几十 px(`:222-225`)。
2. 异步 `import('mermaid')` + ELK `render` → 带官方虚高 viewBox 的 SVG 进 DOM(常到几千 px,图上方空白,mermaid#1984)(`:255-271`)。
3. `requestAnimationFrame` → `measureSvgHeight` → `tightenSvgInk` 按墨迹改 viewBox(`:100-112, :272-276`)。高度再塌一截。卡片里的节点相对视口**往上窜**(C),即使 `scrollTop` 不变。

多图仍逐个完成。每次完成打一次内容区 `ResizeObserver`。

`deferMath` 在整轮 `running` 期间都不把 mermaid 画成 SVG(`ChatTranscript.tsx:131-134`:最后一条助手在 `running` 时不算 `finalAssistantIds`)。`running` 一结束,上述 1–3 在同一窗口发生。过程卡同时强制收合(§4.3)。

**证伪:** 离屏 render+tighten、用最终 bbox 占位后再一次插入,若生成期/收笔后跳动明显下降 → 本条成立。

**证据:** V2。现场幅度待 V1(§11 实验 2、4)。

### 4.3 B-过程卡 — 工具结束瞬间塌高度

`ProcessRow`: `useEffect` 在 `block.running` 变 false 时 `setOpen(false)`(`ProcessRow.tsx:19-22`),CurtainFold 把步骤列表卷起。常与 mermaid 第一次落 SVG 同一窗口:上面塌、下面暴涨。

**证伪:** 禁用过程卡自动收合后,收笔窗口跳动若几乎不变 → 本条只是叠加。

**证据:** V2 机制;贡献比例 V3。

### 4.4 B-整列 — 流式正文让所有气泡重绘,且可能卸掉已画的图

- `items` 一变,`ChatTranscript` 对全部 `items.map`(无按消息 memo、无「只有正在长的 part 订阅文本」)。
- 终稿 `onRepairMermaid` 是内联箭头(`ChatTranscript.tsx:153-155`)。
- `Markdown` 的 `components` `useMemo` 依赖 `onRepairMermaid`(`Markdown.tsx:85`)。身份一变,`pre` 等于换组件类型 → **已挂载的 `MermaidBlock` 可能卸载再挂**。
- `renderCache` 让首帧不是空白,但 remount 仍会再走 `tightenSvgInk`,图再跳一次(C 复发)。

Hermes 桌面端把这条写成铁律:`AssistantMessage` **禁止订阅 streaming 正文**;footer 用 `getMessageText()` 懒读(注释:当 prop 会让整条 ~30Hz 重绘)。

**证伪:** 把 `onRepairMermaid` 收成稳定 `useCallback`,给助手气泡 `memo`,若邻条 mermaid 在 delta 期间不再抽动 → 本条成立。

**证据:** V2(依赖链完整);remount 是否每次发生取决于 react-markdown 调和,现场要用 React Profiler 看 V1。

### 4.5 A-放大 — 滚动跟非单调高度 / 消息锚点钉不住图内墨迹

现行合同(`chat-scroll-ux.md` §4 + `useStickToBottom.ts`)在 A 层已经合理:

- sticky 才自动贴底;手势离钉;回缩不追;overflow-anchor 恒 none;钉态不重绘消息列。

仍会放大 B/C:

- sticky:`contentKey` 含 `last.content.length`(`App.tsx:555-563`),每个字和 RO 两路触发 `followSettleMs`(默认 140ms)后 `scrollToBottom`。高度振荡 = 视口被搬到当时的「底」——底本身在动。
- manual:`captureVisibleMsgAnchor` 钉的是 `[id^=msg-]` **整条消息顶**(`scrollMsgAnchor.ts:14-24`)。opensquilla 同源 API 的注释是:「上面插入一行 / 晚到的图解码后,把这条消息拉回原视口位置」。**图在气泡内部长高或 viewBox 被裁,消息顶可以不动,你正在看的节点照样爬。**

**证伪:** 内容层一次落位且闭合块冻结后,若只关 follow 跳动几乎不变 → A 仍是主因(与本报告相反)。

**证据:** 放大关系 V2;「A 不是震源」是排除性主张,待 §11 实验 1 对照。

## 5. 邻居产品:他们改的是提交纪律,不是换皮

路径均在本机 Workspace,可直接打开核对。类比等级 **V4**(他仓机制,非 Lumen 现场);用来排除「只有我们这种滚动才会跳」和「必须重做整套 UI」。

### 5.1 hermes-agent 桌面端

| 原则 | 他们 | Lumen |
|---|---|---|
| 滚动写手 | `use-stick-to-bottom` 单写手;列表分页/预算渲染**不许碰 scrollTop**(`thread/list.tsx` 注释) | 自研 hook;RO + `contentKey` 两路 follow |
| 生成时看什么 | 用户问句 `position: sticky` 钉在本轮顶,回答往下长(`thread/user-message.tsx`) | 贴**内容底部**。大图高度振荡时视口粘在移动的底边上 |
| 流式 Markdown | Streamdown:remend 只跑**最后一个未闭合块**(`lib/remend-tail.ts`);KaTeX LRU(`lib/katex-memo.ts`);流式高亮 defer 纯文本;reveal 约 33ms 一次 commit,避免「每秒 60 次全量 parse」(`markdown-text.tsx`) | 每个 coalesce delta 全量 react-markdown + highlight |
| 谁能重绘 | 根组件不订阅 streaming 文本 | `items` 驱动整列 map |

他们没有重做整个 App。改的是:滚动单一写手、流式正文只进叶子、本轮开头钉住。

### 5.2 opensquilla

- `scrollAnchor.ts`:锚视口里第一条 durable 消息,补偿 **prepend / 图片解码**;用户手势 cancel 掉延迟修正。
- TUI `stableTranscriptScroller.mjs`:子节点高度若在滚轮帧之后才 deferred 算出来,会在应用切到 manual 之前把视口静默吸回底部。Lumen mermaid 的异步 ELK 属于同一类 deferred 高度。

**不能**从 opensquilla 推出「Lumen 再把消息锚点做精就够了」——对象是插入,不是气泡内 reflow。

### 5.3 产品合同(ChatGPT / Claude / Cursor / Hermes 同构)

生成开始时钉**本轮用户问题或回答开头**,新像素在下方生长。人读已稳定的前缀;不稳定的尾巴在折线下。

Lumen `chat-scroll-ux.md` 意图 A 写成「视口贴最新」。对纯文字短答成立;对 mermaid/表格/widget 等于把眼睛粘在振荡高度的底边。这是规格选择,不是 CSS bug。

## 6. 这不是什么

| 主张 | 判定 |
|---|---|
| 整套前端要重新设计(换框架/重写 App/换视觉) | **否**。壳(侧栏、composer 岛、阅读器、青瓷/Kumo)不是震源 |
| 再写一套更精巧的 sticky 状态机即可 | **否**。A 层合同已够;震源在提交语义 |
| 禁止 mermaid | **否**。要禁的是三次落位,不是物种 |
| 虚拟列表 / 触顶分页 | **非目标**(与 `chat-scroll-ux.md` §5 一致)。Hermes 用 part 预算限制 DOM,仍不碰 scrollTop |

要重订的是对话列里「模型吐字 → 像素落盘」的合同,见 §8。

## 7. 最终诊断表

| 优先级 | 因素 | 层 | 性质 | 证据 |
|---|---|---|---|---|
| 主因(流式) | 整篇 Markdown 每 delta 全量重解析,开围栏改写已画块 | B | 提交语义 | V2 |
| 主因(收笔/读图) | Mermaid 占位 → 虚高 SVG → tighten(C) | B+C | R11 P1 未做 | V2 |
| 放大 | 整列订阅 delta + `onRepairMermaid` 身份打爆 `components` | B | 隔离缺失 | V2 路径 / remount 待 Profiler |
| 叠加 | 过程卡 running→false 强制收合 | B | 同窗口塌高 | V2 机制 V3 比例 |
| 放大(非震源) | sticky follow 振荡底;manual 消息顶锚点 | A | R11 之后仍会放大 B/C | V2 |

一句话:**「不断跳」= 高度非单调(解析 + 图三次落位)发生在眼睛所在的盒子里;滚动在追这个盒子。** 纯文字无围栏对照若明显好转,即可把 A 从主因里排除。

## 8. 合同草案(先落规格再动代码)

建议写入 `doc/chat-scroll-ux.md` 新节「像素何时允许变高」(或独立短文,滚动文只引用)。四条:

1. **闭合即冻结** — 围栏/块一经闭合,该块 DOM 身份与高度不因后续 token 改变。
2. **重活一次提交** — mermaid / 高亮 / KaTeX / 大图:离屏算完最终盒再插入;中间态不进 `.messages-content`。
3. **流式隔离** — `text_delta` 只重绘正在长的 text part;邻条、footer、`onRepairMermaid` 不得换身份。
4. **追更看开头** — sticky 跟本轮已稳定顶(或用户问句),不跟振荡的 `scrollHeight`。此条改意图 A,须改规格,不是改 CSS。

1–3 治震源,可不改滚动状态机。4 是产品选择(对标 Hermes sticky 用户气泡)。

## 10. 对拍清单(给另一份诊断)

请对方报告对每条给 **同意 / 反对 / 未涉及**,反对必须指出替代机制与证伪实验。

1. 跳动的物理来源穷举为 A/B/C,没有第四种(排除 GPU 合成抖动等需 V1)。
2. R11 已修 A 的量纲/二次滚动/误 sticky;现行生成期主因不在这三项。
3. 流式期 `ReactMarkdown` 全量重解析会使已画块重排(有围栏时尤其)。
4. `deferMath` 只推迟 mermaid SVG 与 KaTeX,不推迟 GFM 结构重排与 highlight。
5. 截图中的 SVG mermaid + ↓ = manual 读图,不是 sticky 追底。
6. Mermaid 三次落位(占位/虚高/tighten)是读图跳动的充分机制。
7. 消息级 `restoreMsgAnchor` 不能稳定气泡内 viewBox 变化。
8. `onRepairMermaid` 内联箭头可导致 `components.pre` 换身份、MermaidBlock remount。
9. 过程卡自动收合与收笔落图叠在同一窗口。
10. 邻居产品的有效解是提交纪律 + 钉本轮开头,不是换整套 UI。
11. 修复应先内容层 1–3,滚动状态机尽量不动。
12. 不需要虚拟列表才能消除这种跳。

若对方主因仍写「sticky 与手势抢权」或「overflow-anchor」,请其用 §11 实验 1 解释纯文字对照。

## 11. 现场实验(V1,对拍后一次做完)

复现:桌面 App 或 `npm run dev -w packages/ui-client`;可选 `⌃⌥⇧S` 开滚动诊断 HUD。

| 实验 | 做法 | 若本报告为真 | 若 R11 主因仍在 |
|---|---|---|---|
| 1. 纯文字对照 | 无围栏/表/图的长散文,生成中看视口 | 基本不跳或仅平滑增高 | 仍顿挫跳贴 → A 独立主因 |
| 2. 单 mermaid | 只输出一张流程图,盯收笔后 1s | 收笔窗口跳 2–3 次(占位/虚高/收) | 跳与 sticky 翻转同时且多次「换页」 |
| 3. 读图 + ↓ | 图出现后上滑看图顶,等尾巴还在长或邻条更新 | 图内节点爬、消息顶可不动 | ↓ 反复显隐 = sticky 抖动 |
