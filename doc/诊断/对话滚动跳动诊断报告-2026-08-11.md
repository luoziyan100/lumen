# 对话列滚动「跳转多次、最终落回原处」诊断报告

- 状态: **现行(P0/P2 已落地,主因 P1 待做,待现场 V1)** · 2026-08-11
- 性质: 诊断 + 主会话复核后落地 P0/P2
- 涉及产品: `packages/ui-client` 对话列滚动(`useStickToBottom` + 消息渲染)
- 对应验收: `doc/chat-scroll-ux.md` §3-5「无『中间连续闪过多屏陌生内容、最后又落回』的过山车」

---

## 0. 一句话结论

模型输出界面向下滑动时「中间跳转多次、最后又回到原界面」,根因是**定稿瞬间(mermaid / 大图等异步内容)高度批量突变 + 贴底逻辑与手势抢权**:

- **主因**: `model_step` 定稿时整条消息从「流式暂缓渲染」切到「完整渲染」,多个 mermaid / 大图**逐个异步**渲染完成,每次完成都让内容高度突变一次;sticky 态下 `overflow-anchor: none`,浏览器不做锚点补偿,高度突变直接顶动视口;每次突变又经 ResizeObserver → `scheduleFollow` → `scrollToBottom`,把视口搬到当时的最新底部。多个图 = 视口被搬多次,看到的每一帧都是不同位置的「一页」→ 就是「换来换去、最后稳定回原处」。
- **放大因素**: 贴底基线在两个高度度量(`offsetHeight` vs 含大底垫 padding 的 `scrollHeight`)之间混用,导致流式跟随变成「吞一拍、贴一拍」的间歇跳贴;贴底后还有一帧无条件二次强制滚动,帧级覆盖用户滚动。

---

## 1. 现象

- **现象**: 在模型输出界面(对话列)往下滑动,视口中间跳转多次——一下移到一种「页面」,又换到另一种,换来换去,最后又回到原来的界面。
- **触发时机**: 模型生成中与生成完滚动都会出现(用户确认「两种都有」)。
- **内容特征**: 对话里有 mermaid 流程图 / 大图 / 网页 widget 时出现(用户确认「有 mermaid/大图」)。
- **影响**: 违反 `doc/chat-scroll-ux.md` §3-5 验收;追更 / 回看两种阅读意图都被打断,滚动体验不可用。

## 3. 根因分析

### 3.1 主因 — 定稿瞬间内容高度批量突变(过山车的机械来源)

代码路径完整可见:

1. 流式中 `AssistantContent` 传 `deferMath=true`(`AssistantContent.tsx:25`),`Markdown` 走 `REMARK_STREAM`,**未闭合的 mermaid 不渲染**(`Markdown.tsx:56` 注释:「避免高度狂抖」)。此时高度只随文字增长。
2. **模型一收尾(`model_step` 定稿)**,`deferMath` 关闭,整条消息从「暂缓渲染」切到「完整渲染」:这条消息里所有 mermaid 同时启动异步渲染。
3. 每个 `MermaidBlock` 先渲染「正在绘制…」占位(几十 px,`MermaidBlock.tsx:254`),然后异步 `import('mermaid')` + `parse` + `render`(几百 ms,`MermaidBlock.tsx:118-183`)完成后变成 SVG(大图几千 px)。**多个图不是同时完成,是逐个完成**——每完成一个,内容高度突变一次。大图(`msg-image` 的 base64 图)加载完成时同理。
4. 每次高度突变 → `ResizeObserver` → `scheduleFollow(false)`(`useStickToBottom.ts:321-323`) → 若判定「内容增高」就 `scrollToBottom('auto')` → **视口被搬到当时的最新底部**。多个图逐个完成 = 视口被搬多次,每次看到的都是不同位置的「一页」。
5. sticky 态下 `overflow-anchor: none`(`useStickToBottom.ts:93-94`),浏览器不做锚点补偿,高度突变直接顶动视口,跳得更凶。等所有图渲染完、高度稳定,视口随之稳定——回到的「原来的界面」其实是同一条消息,只是图都渲染完了。

**判定**: V2 部分闭合(文档自述「跳闪主因 = 贴底抢权 + 超长 mermaid/表格高度变化」,代码路径完整;未现场复现)。

### 3.2 放大因素 A — 贴底基线在两个高度度量之间混用

- `contentHeight()` 读 `content.offsetHeight`(`useStickToBottom.ts:149-154`)。
- auto 贴底 rAF 回调与 `pin` 路径把 `lastHeightRef` 写成 `node.scrollHeight`(`useStickToBottom.ts:136, 185`)。
- 而 `.messages`(滚动容器)有 `padding-bottom: 168px + min(22vh,200px)` ≈ **200~370px** 大底垫(`styles.css:1045`),`.messages-content`(RO 观察的内容根)没有。因此 `scrollHeight` 恒比 `offsetHeight` 大几百 px。

后果: 每次贴底后基线被写大几百 px → 下次流式增高时 `shouldFollowScrollHeight` 判定「未增高」→ 基线被重置(`useStickToBottom.ts:169-171`)→ 贴底被吞一次;再下次增高又贴一次。**流式期间的「贴底跟随」变成「吞一拍、贴一拍」的间歇模式**,视口跟着内容一咔哒一咔哒地跳,而不是平滑跟随。生成中滚动时尤其明显。

**判定**: V2(代码推演闭合,量纲不一致是确定的;现场影响程度待 V1)。

### 3.3 放大因素 B — 贴底后还有一帧无条件二次强制滚动

`scrollToBottom('auto')` 里先 `el.scrollTop = el.scrollHeight`(`useStickToBottom.ts:134`),然后下个 rAF **无条件**再设一次 `node.scrollTop = node.scrollHeight`(`useStickToBottom.ts:137-146`)。这两帧之间用户若正在往下滚追更,滚动增量被覆盖——「往下滚被拽回」的帧级窗口,流式期间每次跳贴都会出现。

**判定**: V2(帧级时序推演)。

### 3.4 放大因素 C — sticky 下 `overflow-anchor: none`

`applySticky` 把 `overflow-anchor` 设 `none`(sticky)或 `auto`(manual)(`useStickToBottom.ts:93-94`)。意图是「减轻浏览器锚点乱跳」,但副作用是高度突变时浏览器完全不补偿,视口被顶动的幅度放大。manual 态下 `auto` 反而可能让浏览器自己锚到某个元素上,形成「换页」观感。

**判定**: V2(与主因叠加放大,非独立根因)。

## 4. 最终诊断结论

| 优先级 | 因素 | 性质 | 证据 |
|---|---|---|---|
| 主因 | 定稿瞬间 mermaid/大图逐个异步渲染 → 高度批量突变 → sticky 下贴底反复搬视口 | 交互缺陷 | V2 部分闭合 |
| 放大 A | 贴底基线 `offsetHeight`/`scrollHeight` 混用 → 间歇跳贴 | 代码缺陷(量纲错误) | V2 闭合 |
| 放大 B | 贴底后 rAF 无条件二次强制滚动 | 代码缺陷 | V2 |
| 放大 C | `overflow-anchor` 在 sticky/manual 间切换 | 叠加放大 | V2 |

一句话: **「跳多次、最后落回」主要来自定稿后内容高度反复突变 + 贴底被一次次触发;「滚动不顺」来自基线度量混用。** 纯文字、无大图内容的对话理论上定稿后不应跳——这也正是 §6 实验 1 的对照。

## 5. 修复方案

### 5.0 主会话裁定(2026-08-11)

| 报告主张 | 裁定 |
|----------|------|
| 主因:定稿 mermaid 逐个完成 → 高度雪崩 + sticky 反复贴底 | **采纳** — 与架构一致(无虚拟列表/无触顶分页),解释「跳多次再落回」最好 |
| 放大 A:offsetHeight / scrollHeight 混用 | **采纳 · 实锤** — `contentHeight()` 读 content.offsetHeight,贴底路径写 scroller.scrollHeight |
| 放大 B:rAF 无条件二次 scrollTop | **采纳 · 实锤** |
| 放大 C:overflow-anchor 切换 | **部分采纳** — 放大项,非独立主因;P1 后再调 |
| Claude 式「触顶加载历史未锚定」 | **不适用本仓** — 整会话一次渲染(见 chat-scroll-ux.md §2) |

**已落地**: P0 统一基线 + P2 二次滚动改为「仅内容又增高时」。  
**待做**: P1 定稿高度雪崩(占位/合并 follow)。

按收益排序:

### P0 — 统一贴底基线度量(消除间歇跳贴,改动最小)

- **位置**: `useStickToBottom.ts:136, 185`(auto 贴底 rAF 回调 + `pin` 路径)
- **改法**: `lastHeightRef` 一律只写 `contentHeight()`(即 `content.offsetHeight`),不再写 `node.scrollHeight`。两处与 `scrollHeight` 的耦合是量纲混用的全部来源。
- **验证**: 流式输出时滚动,跟随应连续平滑,不再「顿一拍贴一拍」;跑 `tests/stick-to-bottom.test.ts`(当前纯函数测试不受影响,可加一个断言盖住:auto 贴底后 `lastHeightRef` 等于 content 高度而非 scroller 高度)。

### P1 — 软化定稿瞬间的高度突变(治主因)

- **位置**: `MermaidBlock.tsx` / `Markdown.tsx` 定稿渲染路径
- **改法(可选其一,建议先做 a)**:
  - a) 定稿后 mermaid 渲染完成前先按**预估高度**占位(或复用占位区撑住大致空间),避免几十 px → 几千 px 的突变;多个图最好**一起完成**再一次性落 DOM,减少突变次数。
  - b) 高度突变窗口内对「贴底跟随」做节流/合并:定稿后一小段时间内的多次 `scheduleFollow` 合并成一次,避免视口被搬多次。
  - c) 保留 `overflow-anchor` 行为先验证 b,再决定要不要调。
- **验证**: 含 2-3 个 mermaid 的会话,收笔后滚动浏览经过图的位置,不应再「换页」;`doc/chat-scroll-ux.md` §3-5 逐条过。

### P2 — 去掉贴底后的帧级二次强制滚动

- **位置**: `useStickToBottom.ts:137-146`
- **改法**: rAF 内不再无条件 `node.scrollTop = node.scrollHeight`;改为只在「无手势、无用户滚动增量」时执行,或在 `scrollTop = scrollHeight` 后直接清 `ignoreScrollRef`。
- **验证**: 生成中快速往下滚追更,不应被拽回;对照 `doc/chat-scroll-ux.md` §4「程序化可打断」。

### P3(可选)— 补 hook 集成测试

当前 `tests/stick-to-bottom.test.ts` 只测纯函数,未测 `onScroll/onWheel/ResizeObserver` 组合状态机(集成 bug 靠真机才暴露)。可加一个轻量 DOM 测试(jSDOM 或真实浏览器)钉住「内容增高 → 贴底;用户上滑 → 松钉;定稿高度突变 → 合并一次贴底」。

## 6. 现场确认实验(V1 复现,按此分清主因)

| 实验 | 做法 | 预期区分 |
|---|---|---|
| 1. 纯文字对照 | 一条**纯文字**长输出,生成中滚动 + 收笔后滚动 | 若基本不跳 → 主因确实在异步高度突变;若仍跳 → 缺陷 A(基线)独立作用 |
| 2. 含图会话 | 一条**含多个 mermaid** 输出,等收笔后滚动浏览经过图的位置 | 若「换页」发生在图的位置 → 主因 C 坐实 |
| 3. 观察「回到最新」按钮 | 跳转时看左下/右下 ↓ 按钮是否反复出现又消失 | 出现又消失 = sticky 状态被反复拨动 → 贴底与手势抢权坐实 |
| 4. 定稿瞬间观察 | 一条含图的输出收笔瞬间盯着视口 | 若在收笔后几百 ms 内跳多次 → 高度雪崩坐实 |

> 复现时可用 `npm run dev -w packages/ui-client`(连接 8787 服务)或桌面 App。
