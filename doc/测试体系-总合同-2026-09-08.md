# Lumen 测试体系总合同

状态: v1.2，2026-09-09。本文是测试宪法。行为/组合以 [`testing-matrix.md`](testing-matrix.md) 为真源；缺陷完整字段以 [`testing-defects.md`](testing-defects.md) 为真源。本文建立测试系统，不改变业务行为，不把现有绿测扩大解释为合同已完成。

[PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md

测试代码是机器相，矩阵是测试语义相；任一方变化都必须同步检查另一方。

## 1. 边界

现有仓库已有大量测试文件。文件集合不等于测试体系。体系必须回答：

1. 这条行为合同是什么？
2. 哪些风险和组合会使它失效？
3. 哪个测试在什么环境下证明了它？
4. 哪些路径仍未覆盖？

`npm run verify` 是本地统一执行入口，不是覆盖证明。它不自动证明真实 WebKit、原生设置流程、LaunchAgent 交接、长任务性能或正式分发。

本阶段不做：生产逻辑修复、全面 CI、正式分发、为数量指标新增重复测试。

## 2. 分层与覆盖性质

| 层级 | 名称 | 允许依赖 | 证明范围 | 典型位置 |
|---|---|---|---|---|
| L0 | 类型/静态 | TypeScript、源码合同脚本 | 类型和静态约束 | 两包 `tsc --noEmit`、主题合同 |
| L1 | 纯单元 | 确定性输入、有限替身 | 单函数/纯状态转换 | runtime、storage、ui reducer |
| L2 | 模块集成 | 真实 SQLite、WS、FS、进程、Seatbelt | 模块边界和持久事实 | service、storage、workspace |
| L3 | 工作流/组合 | 多模块真实路径、故障注入 | 跨身份、生命周期、并发 | governance、invariants、replay |
| L4 | 原生交付 | 隔离 HOME、真实 WebKit、launchd、Tauri | 用户可见和安装交接 | Computer Use / 安装记录 |
| L5 | 受控回放 | 录制模型/工具结果、隔离数据根 | bad case 重建和质量评估 | replay_recorded、diagnostic pack |

替身只允许在模型端口录制/重放和 HTTP 罐装响应。L2–L5 不得用全 mock 代替真实内核。

覆盖性质：

- `direct`：直接调用被声明合同的生产入口并断言行为。
- `indirect`：上层工作流间接穿过该入口；只证明实际走到的路径。
- `static`：源码、类型或协议形状；不能替代运行时。
- `native`：真实 WebKit、Tauri、launchd、Seatbelt 或 Darwin 文件语义。
- `uncovered`：无证据或环境未满足；不得从邻近测试推断通过。

Darwin 用例在非 macOS 必须 `skipped: platform`，跳过不得记通过。临时私有探针发现缺陷后，修复须转为稳定 `CT`/`AT`/`RP`，不能只留在 `/tmp`。

## 3. 合同追踪

一行一个可独立判定的必需行为，不用 Round 编号当身份。字段见矩阵头部。状态：

- `uncovered`：无公开证据。
- `partial`：有相关测试，但缺组合、真实环境、候选绑定或合同子句。
- `covered`：绑定候选上该行为测试已执行并通过。
- `accepted`：证据与当前候选、合同语义和环境相符。

缺少组合路径、真实环境或证据时只能是 `partial`。`pass count` 只是规模。

测试 ID 合法形态：`UT-<module>-NNN` / `IT-<boundary>-NNN` / `CT-<risk>-NNN` / `AT-<surface>-NNN` / `RP-<contract>-NNN`。

- **绑定 ID**：必须出现在测试标题或源码；`file` 必须真实包含该字符串。`covered` 仅当绑定候选上该测试已执行且未 skip。
- **历史 unbound ID**：同一语法；本阶段只在矩阵登记，不改名。`candidate_id` 必须 `unbound`。实体是 [`testing-historical-ids.json`](testing-historical-ids.json) 中的现存测试文件，外加 40 位 git commit **或** 现存 evidence 文档，以及文件 sha256。禁止标 `covered`。
- checker 必须双向：`manifest → 矩阵/源码` 且 `矩阵每个 test_id → 绑定条目或 historical-unbound`。重复和悬空引用为零。没有绑定实体的 ID 不得标 `covered`。

## 4. 风险维度

每次改动至少评估：身份、生命周期、并发、持久化、权限、交付。必测组合列在矩阵 §2。组合必须有 `combo_id`，不得以 `governance-roundN.test.ts` 文件名证明覆盖。

## 5. 统一入口与报告

```text
npm test --workspace @lumen/agent-service
npm test --workspace @lumen/ui-client
npm run check:theme -w packages/ui-client
npm run verify
```

报告字段：`candidate_id`、工作树摘要、命令和退出码、测试层级、`behavior_id`/`combo_id`、环境、证据路径、失败与重开缺陷、未覆盖路径。详见矩阵 §6。

## 6. 候选冻结

```text
代码/测试写入
→ 变更影响图（behavior_id + combo_id）
→ 失败复现与修复
→ 受影响层级及组合回归
→ npm run verify
→ candidate manifest（git diff、文件 hash、环境摘要）
→ 冻结候选
→ 主模型独立验收（禁止写入）
```

验收发现缺陷：当前候选作废；修复必须新候选。验收过程中补测试或改断言后，原候选证据作废。

`MAIN_PASS` 仅当同时满足：

1. 本轮范围内每个行为 ID 为 `accepted`
2. P1/P2、reopened defect 均为零
3. 必测组合矩阵无 `uncovered`
4. L4/L5 必需交付证据已绑定同一候选
5. 未覆盖清单已明确归属，不存在用绿灯推断的隐藏路径

## 7. 缺陷闭环

完整字段只写在 [`testing-defects.md`](testing-defects.md)；矩阵 §5 只做索引。同一根因类连续出现两次，暂停局部补丁，先修身份/状态/事务模型。P1 出现时停止扩展功能。原始反例消失但组合未覆盖，状态仍为 `partial`。

每轮只比较：新增行为/组合、重开缺陷、`uncovered` 数量。不用 Round 数或测试总数表示进度。
