# agents/budget/
> L2 | 父级: ../CLAUDE.md

- `index.ts`：在原生输入/输出 processor 和委派钩子处串行准入父子共享预算，threadState 持久化原生步骤收据与未结算预留；按受信父/委派身份、原生 response messageId、step/retry 去重，费用仅按当次明确模型价格计算。

默认不限额。设置上限后，在下一次模型请求前检查累计用量与同父并行预留，文本输入用 UTF-8 字节数加协议余量，输出预留当前 maxOutputTokens 或 4096；实际响应用 provider usage 结算。模型价格与上下文窗口从会话绑定的不可变模型注册快照读取，忙会话切换全局模型不会污染旧步骤；直接使用工厂时仍可注入按 resourceId 解析的回调。该机制是预估准入，不承诺供应商账单的绝对硬限额；多模态与 provider 计量差异可能超出预留。未知 usage 或硬中断未结算调用会阻止后续受限准入；未知价格不当作零费用。调高上限不会消除未知计量，用户可明确取消相应限制或新建研究。

原生恢复/后台续轮可在同run内重置局部step，故不能把run/step当作唯一模型请求。输入/输出processor共享同一ID的原生请求state，将准入key与scope传到输出结算；不在输出阶段重读可变Controller run。重复准入仍拒绝、重复输出仍去重，旧收据原样保留计入累计。

只存派生计量，不保存消息、不重建调度。父线程内事务队列防止并发专家使用同一剩余额度；输出在工具与空回答纠正之前结算，失败与取消不抹掉已发生消耗。

已有任务首次接入以 Controller 主用量加专家累计用量建立一次基线，历史费用未知不会按现价补算。迟到真实 usage 可替换中断占位收据，重复回调不重复收费。输出预留收窄到剩余额度；公开最近一次主模型实际输入和当前上下文窗口，供 UI 区分累计预算与当次上下文占用。
