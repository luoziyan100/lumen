- `Composer.tsx`：原BorderBeam光边、圆形停止与模型选中菜单，欢迎态按需准备真实身份，原输入卡左上角「+」的文件/研究技能二级菜单、当前稿芯片与底栏模型选择，技能只加入草稿不触发发送；发送/停止共用互斥位置，可停止期间输入保留为草稿，Enter和表单均不提交；模型选择运行中仍可提交并延迟到新对话生效，完整配置继续受服务级运行状态保护；草稿自适应高度上限168px，回到最新按钮锚在坞上沿，订阅当前项目/会话草稿；卸载只释放 UI 订阅，已确认的上传与原生提交继续面向原会话。
- `draft.ts`：按项目/会话保存草稿和提交快照，提交先冻结正文/附件/当前稿快照，再等待欢迎态准备，上传中切会话不改提交目标；正文可本地恢复，File 与失败材料留在进程内；失败显式合并到后来的草稿，已上传文件用服务路径复用。
- `Attachments.tsx`：待发图片的 Blob 缩略图与预览；删除/卸载释放 URL，不执行附件脚本。
- `Slash.tsx`：原斜杠菜单通过当前任务技能 API 过滤与键盘选择；显式激活只加入草稿，迟到响应不覆盖后来的文字。
- `Progress.tsx`：任务/主子累计用量和进行中工具只读呈现；上下文提示仅采用上次主请求真实输入量与配置窗口，60%起显示，未知隐藏，不用累计消耗冒充窗口占用。
- `Specialists.tsx`：共享Disclosure呈现服务端专家历史的折叠目录；状态轮询同一会话串行，避免旧响应回退新状态；用户显式补充新任务后继续原专家，202 等待原生审批卡片，不缓存提交成功/等待审批文案，禁止重发或重放历史工具。
- `process/`：原生推理与工具轨迹按轮次有序呈现，恢复思考/过程卷帘与流式开合，默认不展示工具JSON。
- `transcript/`：原生消息上的历史附件、复制反馈、长正文折叠与轮次导航，文件只交当前工作区阅读器，轮次预览与对应圆点对齐，遵守chat-stage窄栏隐藏。
- `question/`：原生 ask_user 的单选、多选与自由补充；复用原编号竖排ask-user卡，挂输入坞；按框架规定回复字符串或字符串数组。
- `welcome/`：本地预留会话身份与完整Composer衔接；发送或使用技能才准备原生会话，渲染和普通输入不创建空会话。
