# studio/ — Topic and whiteboard workspace
> L2 | Parent: ../CLAUDE.md

The board is the topic's co-drawn canvas: the user and the AI draw on the same Excalidraw sheet (R2); the reading is the AI's account of one material, read in the Reading view; conversation lives in the sprite. The takeaways are the user's own words (R13). Product rules live in doc/studio/.

- `StudioApp.tsx`: sole workspace shell; in the music kit its center header ends with a speaker button (`aria-pressed`, title via Tips) in one `head-trail` group before the right reopen toggle; it flips the same `instrumentSounds` preference as Settings, so the two stay in sync. Mounts `Tips` once, so every `title` in the app shows as the same Kumo-styled tooltip; aligned 50px panel headers and 8px gaps, persisted topic, busy-session selection, side panes, split/full reader and the window-level sprite. Full reader preserves the mounted board and its camera. A conversation card's element id goes to the board as `{elementId, nonce}`. It owns the topic's one conversation feed (`useSessionFeed`) and lends it to the sprite; the shell itself selects only what it shows (the reading_write signal, whether the conversation runs, the open conversation's questions) with `useFeedSelect`, so a streamed token re-renders the sprite and never the whole workbench (measured: whole-tree re-render at about 56 commits a second stalled WebKit while a reading was written). Each placeholder view (Map, Ideas, All) is its object alone, centred: the cork board, the lamp, the type case; 「还没开放」 (`notOpen`) is the container's aria-label, never visible text; each object is built once, as it carries no data. `say` posts a visible user message to the given conversation, else the open one, else a new one (opened first, then the sprite follows it); a refusal (R1's 409) comes back as readable text and nothing else is sent. The empty Reading view's typewriter shows the picked material's title, else the one open beside, else the only one. A request ends at the first section, at the run's end, or when an idle conversation already answered it (a short run can end before the view sees it running). Reading is the default view.
- `Panes.tsx`: persisted side visibility and split ratio, physical-key shortcuts, accessible toggles and 8px splitter; board/reader minimums are 360/420px.
- `TopicPanel.tsx`: topic list and 3s status polling, inline creation and the settings entry; experts live inside settings. The takeaway box sits in the free space under the list, over the scroller's bottom. A ResizeObserver on the scroller and the list shows it only with 16px of air above and below. It is absolute, so folding it never moves the list. Its front card carries the selected topic's newest takeaway. Rows are ActionRows (rename, copy ID, archive, delete); a refusal shows in the pane's alert line, and archiving or deleting the selected topic selects the next one, else the previous, else none; a delete moves the selection before its request (a topic being deleted answers 404) and back on a refusal.
- `ViewNav.tsx`: owns the view ids (`VIEWS`) and which are available (Reading first since P1-2, then the board and the takeaways; map/ideas/all stay honest placeholders); labels come from the catalog (`studio.views`), so the width test re-measures when the language changes. Six icon/text views; symmetric room for the edge controls (every direct child of the header except the navigation and its twin: reopen toggles, the speaker) keeps navigation centered. A hidden full-width copy determines when only icons fit; aria labels remain available. Icon-only tabs carry their label in `title`, which the app's one tooltip layer (`components/Tips.tsx`) draws in Kumo's style under the tab; with the labels shown there is no title. The tab element never changes as compact flips (a swap made WebKit report a ResizeObserver loop on load).
- `Board.tsx`: the board view around the canvas. The selected sheet's lazy BoardCanvas (keyed by sheet; Board sets EXCALIDRAW_ASSET_PATH before the chunk loads) sits inside CanvasBoundary: a chunk that fails to load or an editor crash leaves one line in its place, and the strip and the app stay. The sheet strip is a 38px bar under the canvas, not an overlay, so Excalidraw's toolbars and menus never meet it at any width: board glyph + number, full title in title/aria-label, folded dimmed, a dot on the run's target while the AI draws, a 「⋯」 menu per tab (R17: a sheet with content asks first in a Kumo dialog with its stroke count and the takeaways leaning on old blocks; the run's target is disabled with the reason), ＋. Over the canvas, all on solid surfaces: the easel alone in the middle when there is no sheet, or on a live sheet with no stroke until the first stroke or the AI's draw there (over a canvas strokes go through it); the folded words; the AI-drawing notice; 「AI 擦了 N 笔」 with restore and keep (R5); the gone-element notice for a card whose element left. A card's element is located through the topic's element route, its sheet selected, then BoardCanvas brings it into view. The sediment row (S9c) opens under the canvas with the AI's invite question (Skip hides it until a newer invite).
- `BoardCanvas.tsx`: one sheet's Excalidraw editor and its sync. The first scene seeds it; later scenes merge in by reconcile. The user's changed elements save 600ms after a change, only what the service lacks (in batches of 2000, ≤8 new images each); the service's `kept` copies replace ours. An AI op is laid out with the page's fonts (loaded first), committed, and only then enters the scene, outside undo, so the user's next save never claims the AI's strokes. The viewport saves 600ms after a scroll and opens where the user left it. A glance (PNG, longest side 1568) goes up after AI writes and before each send (draft.ts's `beforeSend`), only while the canvas is on screen and the scene changed. A folded sheet is view mode and saves nothing. Language follows the app, theme the html color-scheme; the menu keeps search only. The library, Help and the sticky note have no prop to turn them off in this snapshot, so studio.css hides exactly those three under `.board-canvas`.
- `canvas-sync.ts`: BoardCanvas's sync rules outside React, so tests run them against the real library: Ledger (which element versions the service has), mergeRemote (reconcile at the stored version: restore bumps versions of elements without an index, which would let a remote copy outrank the user's newer edit), layOutOp (a draw converted with its stored ids; an arrow to an existing element binds through a copy in the same batch and the real element only gains the arrow; connectors are aimed centre to centre; an update patches and re-measures text; tombstones are never revived), viewportOf and sceneVersion (the service's sum).
- `useBoard.ts`: sheet selection stored on the service (R16; an older service without the route, 404/405, still switches locally; any other failure to store the pick is shown in the board error until a later pick is stored), the run target, the selected sheet's canvas scene by ETag, deleting a sheet (R17: confirm round trip, follows the service's neighbour selection, an older service says deletion is unsupported), restoring or keeping the AI's erase, which sheet holds an element (the topic's element route; another topic's element is a 404), refresh from conversation tool signals, with a 5s list/ETag fallback only while running. The user's strokes save from BoardCanvas, not here.
- `Takeaways.tsx`: the Takeaways view (S8) and the one input (S9): entries newest first in dashed frames (Unverified), the quoted marker expands the original, evidence chips point at old blocks: since the canvas (2026-11-19) they show the title only and never jump, or report the deleted board, inline edit (revision rows on the service) and delete-asks-once; `OfferRow` renders the AI's offer as the user's own sentence with every deleted fragment struck through — click restores, click again re-deletes, Keep sends the final text for the service's delete-only re-check; an older service gets a clean unsupported line. With no entry and no offer, the view is the flower press alone, centred: no text and no 「写一条沉淀」 (a takeaway then starts from the board's invite row or the reading window); an entry brings the button back; an entry, an offer or the open composer removes it. No line explains the empty view or the offers.
- `useSediment.ts`: entries and offers for the topic, refreshed by conversation signals, topic activity and board-view changes (deleted links depend on board state); create/confirm/dismiss/edit/remove with the `sediment.*` error codes; a rev conflict raises a flag so the composer keeps the typed text (S10). `newestTakeaway` picks a topic's entry by `createdAt` (an edit does not make it newer) for the box's card.
- `Materials.tsx`: title/link filtering, upload in the header, descending material list, fixed-width kind icons and title/link rows. Removing a reference keeps the library original; opening a source enters split reading. Each row has 「写解读 / Write a reading」 (sends the visible request through the host and switches to Reading; disabled with the reason while the target conversation runs or waits) or 「打开解读 / Open reading」 (switches only, sends nothing); a refusal shows in the pane's alert line. Once the list has loaded empty, the card cabinet stands alone (upload is in the header); it never flashes during loading.
- `Reading.tsx`: the living Reading view (S5) and its selection window (S6); an active widget renders through `ReadingWidget.tsx` and the view keeps its param values, runtime failures and questions. One centred 960px column whose prose, headings, quotes, tables and Mermaid diagrams (`MermaidBlock`) stay within 700px while sandboxed interactive HTML widgets (`WidgetFrame`, up to 3 active by default, extra slots opened by Kumo button; `__widgetSendMessage` routes straight back into the topic conversation via `onWidgetSend`) use the full 960px column width and can expand in place via `position: fixed` without reparenting or remounting the iframe (keeps interactive state and single load, leaves a same-height slot placeholder, switches `fillHeight` on a solid light stage, closes `AskWindow` first so one `Esc` handles it — including `Esc` pressed while focus is inside the expanded iframe via `onEscape`, which is only bound when expanded — restores scroll position and natural height on collapse, consumes no extra auto-run slot); a paper block is followed by its quote line (original language, quieter, the chip at its end), an inference block ends in its dashed chip (paper chips open split reading at the page; inference chips are dashed). An answer shows in one place only: with the sprite's conversation open (docked or floating) the window is the quote and the input, it closes once the question is sent, the conversation jumps to the newest message, and a footprint makes the conversation scroll to that question and light it briefly (switching to its conversation first); with the conversation closed the exchange runs in the window, and opening the conversation closes a window that shows answers. Esc, × and a press outside close the window. Only a selection that starts and ends in one prose paragraph's text opens `AskWindow` under it, or above it when it would not fit in the visible part of the scroller; it never covers the sentence. The window shows the exchange on that quote from the shared subscription (replies rendered by `components/Markdown` at window size: body-size headings, wrapping code and quotes, scrolling inside the window's 360px), Enter sends and Esc closes (from anywhere), follow-ups continue the exchange's conversation, and 「把我的话记成沉淀」 shows only once a question was asked and keeps only typed words (the input, else the person's last words; never the quote or the reply). Prose draws bold, code and `$…$` / `$$…$$` formulas (`prose` + `ProseText`); headings, table cells, captions and the window's quote are drawn the same way. A formula is KaTeX but its source stays in the shown text: `shownOffset` maps a selection through each formula's data-start/data-end and takes it whole, and a footprint that starts or ends inside a formula widens to hold it (`wholeMath`). A footprint that crosses a mark keeps both. Footprints are inline `role="button"` spans (focusable; Enter/Space or click reopen the exchange) so a quote that starts mid-line wraps like text; a real `<button>` is an atomic inline box and pushed the quote onto its own lines. A footprint never disappears (owner decision 2026-11-21, `placeFootprints`): a sentence the AI changed since the question keeps a dashed footprint on the closest sentence, and one with nothing left to sit on keeps a 22px mark at its paragraph's end that leaves the line height alone; either still opens the exchange with the original quote. Only two states are shown, unchanged and changed; how much it changed is never measured as a threshold. While a run continues after the first section, the state line under the last section says the next one is being written (`more`), and the empty state has no state line: the typing typewriter is the state. The scroller pads the side where the sprite's figure sits (from `onFigure`, re-measured on resize), so no line runs under it; the text never narrows below 360px for it. The header holds the title only. With no reading, `ReadingStart` is the typewriter alone, centred: no text, no button (writing starts from the Materials row); the typewriter types only while the requested reading has no section.
- `ReadingWidget.tsx`: one active reading widget, split out of `Reading.tsx` (2026-11-20). The bar holds the name, a footprint mark once the person asked about the widget, the ask button (both hidden while expanded) and expand/collapse; under the mounted `WidgetFrame` the host draws the declared params (range = native `input[type=range]` on tokens with readout and unit, toggle = Kumo `Switch`, choice = Kumo `Select`), and a page that threw within 3s of starting gets one quiet failure line with 「请 AI 修正」. The row and the line live inside the stage, so they travel with the expanded view; when expanded they re-declare the light surfaces and `data-theme="celadon"` re-derives Kumo's colours from them. It owns no state: `ReadingView` keeps values (by storage key), failures (by block id and html generation) and questions, so a rewrite, an expand or a question never resets them. The `WidgetFrame` is keyed by `widgetGeneration(block.html)` (2026-11-21): reading_patch keeps the block id, so without the key a changed html would finalize again into the running iframe (top-level `const` redeclared, listeners and timers doubled); a new generation mounts a fresh iframe and starts with no failure, while values, title and caption changes keep the iframe and reach the page by `WIDGET_PARAMS`. A widget question opens `AskWindow` under the widget, anchored to its live box (it follows late iframe resizes), never above it; its exchange is every question on that widget (section label + title), and the quote is rebuilt from the current values when sent (`askWidgetText`, two lines). 「请 AI 修正」 sends `MODEL_TEXT.widgetFix` (material, section, widget title, error text, item and block ids, asking for reading_view(blockId) then reading_patch) through the same path as a widget's own message.
- `widget-params.ts`: the value rules behind those controls (P2). Values never reach the service: localStorage `lumen:widgetParams.v1:<topicId>:<itemId>:<sectionId>:<widget title>`, the n-th widget in the section only when it has no title, so a widget inserted before it moves nothing; every read and every push into the iframe passes `fitValues` against the current declaration (unknown names dropped, numbers clamped, wrong types and vanished choices back to the default), so a rewrite that keeps the names keeps the person's values. `widgetQuote` / `paramsLine` write the question's two lines in the model's Chinese (toggle 开/关, choice by label, range with unit); `widgetTitleOf` reads the title back. Known limit: a rewrite that changes the title starts from the defaults; two widgets with one title in one section share one set of values.
- `ProseText.tsx`: the one drawer of reading text (`marked`, `Rich`): strong, code and whole KaTeX formulas (rendered once per TeX, cache capped at 500). The Reading view and the conversation's ask bubble both use it, so a formula looks the same wherever a quote goes.
- `reading-ask.ts`: pure helpers. `prose` turns a prose block into the text the reader sees plus its `**bold**`, `` `code` `` and formula marks (`$…$` not followed by a digit and not padded by spaces, so prices stay text; `$$…$$` displays; `\$` stays literal; models write them anyway; no other Markdown, prose is not a document); quotes, footprints and `readingAsks` all work on that shown text, and `parseAsk` drops `**` from quotes asked before the marks were drawn. The question message format lives in `MODEL_TEXT.askReading` (`> quote` lines, `— 解读《item》· N. section（段 blockId）`, a blank line, the person's words; the block id since 2026-11-21, so a footprint finds its block after a reading_patch and the model can patch it without a reading_view) and is parsed back by `READING_PLACE`; the service reads the same format with its own parser (`mastra-service/src/studio/reading-question.ts`, so sediment counts only the words), bound by `tests/reading.test.ts`; footprints are rebuilt from conversation messages, never stored. `placeFootprints` places every sentence question: exact in its own block (or, with no block id, in every paragraph holding it), else edited on the sentence with the highest character-bigram likeness in its block, else its section, else the reading, else a mark at the block's edge (also when the place is taken). `readingAsks` keeps the questions of one reading: every sentence question about its material (they always show somewhere), or a widget question whose section label and title (`widgetIdle` for an untitled widget) match one of its widgets; `askWidgetText` keeps a widget question's two quote lines where `askText` squashes a sentence to one. `readingSignal` is the ids of completed `reading_write`, `reading_insert` and `reading_patch` calls; `latestReadingWrite` returns the current turn's (after the last user message) latest completed call's `{callId, itemId}` so `StudioApp` auto-focuses the Reading view when the AI writes spontaneously in chat; a write before the person's latest message is old news even when history loads late; `answered` says an idle conversation already replied to a request; `sendErrorText` maps a native send refusal through the error catalog.
- `useReading.ts`: `useReading` loads the topic's reading list and the shown reading (the picked material, else the newest) by ETag, refreshed by the reading signal plus a 5s fallback only while the topic runs (the board's rule); the list is keyed by the topic it was read for, so a topic switch never asks the new topic for the old topic's reading; a material missing from the list has no reading yet and is not fetched (the list's next refresh brings it), so a write request costs no 404; `useTopicAsks` gathers questions from every conversation of the topic: the open one live, the others from stored history keyed by their last message.
- `reading.css`: the Reading view's own sheet: the in-view scroller (`overflow-x: hidden`, page never scrolls), the 960px column with 700px centred prose/tables/diagrams and full-width widgets, in-place expanded widget stage (`position: fixed`, solid `#ffffff` light surface, `.studio-center:has(.reading-widget.is-expanded)` raised to `z-index: 50` above glass side panes and floating sprite), the widget bar's ask button and footprint mark, the host-drawn control row and the quiet failure line (light surfaces re-declared when expanded), the quote line, chips, footprints, the window (solid surface), the material row action and the empty view's start block.
- `Sprite.tsx`: reports whether its conversation is open (`onShown`) and passes `reveal` on to Conversation; reads the full view of the conversation feed StudioApp lends it (it never opens its own) and owns one useSpriteExpression snapshot shared by both renderers. It reports its figure's viewport box (`onFigure`, null when docked) so the Reading view keeps text clear of it. Body/avatar mount changes during opening and closing never reset the expression clock. Existing 60×92 hitbox, anchors, drag, dock, unread handling and session controls remain here. Its conversation list uses ActionRow with a deferred click (the list closes on a pick), copies `topicId:taskId`, and has no 「新对话」 button (the header ＋ stays); leaving the open conversation opens the next one, else a new one.
- `RowActions.tsx`: ActionRow, the shared row of both lists with its 「⋯」 menu (Rename · Copy ID · Archive ─ Delete, R18–R21) and double-click rename; RemoveDialog, the one delete confirmation, also used by Settings › Archived. Archive and Delete are off while the row runs or waits. It calls back and never talks to the service.
- `SpriteFigure.tsx`: pure A04 renderer; compact uses the supplied 2x/3x sources and desktop uses 452px Retina derivatives. Both sizes share five faces, one persistent neutral silhouette and fixed facial overlays; PNG masters are never imported.
- `SpriteFigure.css`: float/think/wait/speak motion on one wrapper, invariant neutral shadow, glow, face masks and opacity cross-fades. Hidden documents pause motion; reduced motion removes animation and transitions for both renderers.
- `SpriteFace.tsx`: pure circular A04 avatar renderer and head source map; consumes the exact snapshot used by the body. Its facial overlays leave the neutral hair/outline invariant.
- `sprite-face.ts`: state mapping, single-timer FaceDriver and useSpriteExpression lifecycle. Idle blinks after 4–7s for 120ms; speech alternates after 180–260ms. Hidden/reduced owners schedule no expression timers; unmount cancels the owner.
- `objects/`: two desk-object kits (the instruments: box, cabinet, typewriter, easel, press, cork board, lamp, type case; the music set in `objects/music/`), the slot registry and their React hosts; see `objects/CLAUDE.md`. A view names only its slot and data through `DeskObject`; StudioApp provides the kit and the sound switch from the appearance preference. They are decoration over empty space: never focused, never in the way of a control.
- `sprite-desktop/`: retained native entry/bridge and local preference; centrally disabled, with no settings entry or projection. Its own window uses the same A04 renderer and pauses its owner while invisible.
- `sprite-place.ts`: pure nearest-edge anchors, viewport clamping, legacy migration, 4px drag threshold, 16px keyboard moves and open/close/reduced keyframes. Resizing changes display clamping, never the stored anchor.
- `useSpriteMove.ts`: pointer capture and drag/click separation, ref-only motion during drag, anchor persistence on release, and reversible Web Animations. During transitions inert shields the outgoing form; no duplicate animation layer is created.
- `useSpeaking.ts`: current native assistant text projects through stream-pulse; collapsing keeps text updates and opening reuses the subscription.
- `studio.css`: token-based shell geometry, typography, controls, pane/reader layout, view navigation, the board's strip and solid notices (and the three hidden Excalidraw controls), materials and sprite interaction chrome, and where the box and the cabinet stand. Shared character rendering lives in SpriteFigure.css.

Language: every visible string here comes from `useT().studio` (or `t()` outside components); service errors arrive already in the UI language. The objects' drawn labels come from `studio.objects`. No literal UI text in this folder; `npm run check:i18n` enforces it.

Subscription flow: StudioApp's useSessionFeed → Sprite reads the full view (useFeedView: Conversation, speaking); StudioApp selects the reading_write signal, the running flag and live questions (useFeedSelect) for the Reading view; both at most once per frame; no second stream.

Expression flow: session → spriteState → one useSpriteExpression → SpriteFigure + SpriteFace. Position and window lifecycle never flow back from the art layer.
