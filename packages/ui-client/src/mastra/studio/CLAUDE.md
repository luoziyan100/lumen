# studio/ — Topic and whiteboard workspace
> L2 | Parent: ../CLAUDE.md

The board is the topic's shared draft; the reading is the AI's account of one material, read in the Reading view; conversation lives in the sprite. The board stays read-only to the user; the takeaways are the user's own words (R13). Product rules live in doc/studio/.

- `StudioApp.tsx`: sole workspace shell; aligned 50px panel headers and 8px gaps, persisted topic, busy-session selection, side panes, split/full reader and the window-level sprite. Full reader preserves the mounted board and its camera. It owns the topic's one conversation feed (`useSessionFeed`) and lends it to the sprite; the shell itself selects only what it shows (the reading_write signal, whether the conversation runs, the open conversation's questions) with `useFeedSelect`, so a streamed token re-renders the sprite and never the whole workbench (measured: whole-tree re-render at about 56 commits a second stalled WebKit while a reading was written). `say` posts a visible user message to the given conversation, else the open one, else a new one (opened first, then the sprite follows it); a refusal (R1's 409) comes back as readable text and nothing else is sent. The empty Reading view's 「写解读」 targets the picked material, else the one open beside, else the only one, and calls the row's own `writeReading`. A request ends at the first section, at the run's end, or when an idle conversation already answered it (a short run can end before the view sees it running). Reading is the default view.
- `Panes.tsx`: persisted side visibility and split ratio, physical-key shortcuts, accessible toggles and 8px splitter; board/reader minimums are 360/420px.
- `TopicPanel.tsx`: topic list and 3s status polling, inline creation and the settings entry; experts live inside settings. The takeaway box sits in the free space under the list, over the scroller's bottom. A ResizeObserver on the scroller and the list shows it only with 16px of air above and below. It is absolute, so folding it never moves the list. Its front card carries the selected topic's newest takeaway.
- `ViewNav.tsx`: owns the view ids (`VIEWS`) and which are available (Reading first since P1-2, then the board and the takeaways; map/ideas/all stay honest placeholders); labels come from the catalog (`studio.views`), so the width test re-measures when the language changes. Six icon/text views; symmetric room for pane toggles keeps navigation centered. A hidden full-width copy determines when only icons fit; aria labels remain available.
- `Board.tsx`: sheet tabs (board glyph + number, full title in title/aria-label, folded dimmed, a dot on the run's target while the AI draws; each tab has a 「⋯」 menu to delete the sheet — shown on hover/focus, always on the selected tab, next to ＋ when one sheet hides the strip; a sheet with blocks asks first in a Kumo dialog, the run's target is disabled with the reason in title), the folded-selection hint, the easel under the no-sheet line (the line keeps its place; the easel is 320 wide and scales down only when the height under the line is short; the pan handler skips it), the deleted-sheet notice (catalog `studio.board`) for a card into a deleted sheet, read-only blocks (current blocks carry a 'write a takeaway from this block' affordance, S9b; settled blocks show the kept mark), pan/zoom, frame and tool activity; at most two live widgets. Hidden zero-width boards do not reflow. The sediment row (S9): when the selected sheet is full, a one-line input opens under the canvas with the AI's invite question and the invited blocks pre-linked (Skip hides it for that sheet until it changes); the from-block entry opens the same row; offers show above the input; a rev conflict (S10) keeps the typed line and reloads the board.
- `layout.ts`: pure 1–3 column display layout with 300–440px columns; stored server coordinates remain untouched.
- `Block.tsx`: text, ladder, table and sandboxed widget rendering, source navigation and superseded presentation; Markdown/Mermaid must fit their column. Current blocks offer 'write a takeaway from this block' (S9b); settled ones wear the kept mark.
- `useBoard.ts`: sheet selection stored on the service (R16; an older service without the route, 404/405, still switches locally; any other failure to store the pick is shown in the board error until a later pick is stored), the run target, deleting a sheet (R17: confirm round trip, follows the service's neighbour selection, an older service says deletion is unsupported), whether a block still exists, refresh from conversation tool signals, with a 5s list/ETag fallback only while running.
- `Takeaways.tsx`: the Takeaways view (S8) and the one input (S9): entries newest first in dashed frames (Unverified), the quoted marker expands the original, evidence chips jump to the block's board or report the deleted board, inline edit (revision rows on the service) and delete-asks-once; `OfferRow` renders the AI's offer as the user's own sentence with every deleted fragment struck through — click restores, click again re-deletes, Keep sends the final text for the service's delete-only re-check; an older service gets a clean unsupported line.
- `useSediment.ts`: entries and offers for the topic, refreshed by conversation signals, topic activity and board-view changes (deleted links depend on board state); create/confirm/dismiss/edit/remove with the `sediment.*` error codes; a rev conflict raises a flag so the composer keeps the typed text (S10). `newestTakeaway` picks a topic's entry by `createdAt` (an edit does not make it newer) for the box's card.
- `Materials.tsx`: title/link filtering, upload in the header, descending material list, fixed-width kind icons and title/link rows. Removing a reference keeps the library original; opening a source enters split reading. Each row has 「写解读 / Write a reading」 (sends the visible request through the host and switches to Reading; disabled with the reason while the target conversation runs or waits) or 「打开解读 / Open reading」 (switches only, sends nothing); a refusal shows in the pane's alert line. Once the list has loaded empty, the card cabinet stands above the empty line; it never flashes during loading.
- `Reading.tsx`: the Reading view (S5) and its selection window (S6). One centred serif column (≤700px) with numbered sections; a paper paragraph is followed by its quote line (original language, quieter, the chip at its end), an inference paragraph ends in its dashed chip (paper chips open split reading at the page; inference chips are dashed). Only a selection that starts and ends in one paragraph's text opens `AskWindow` under it, or above it when it would not fit in the visible part of the scroller; it never covers the sentence. The window shows the exchange on that quote from the shared subscription (replies rendered by `components/Markdown` at window size: body-size headings, wrapping code and quotes, scrolling inside the window's 360px), Enter sends and Esc closes (from anywhere), follow-ups continue the exchange's conversation, and 「存为我的沉淀」 keeps only typed words (the input, else the person's last words; never the quote or the reply). Footprints are inline `role="button"` spans (focusable; Enter/Space or click reopen the exchange) so a quote that starts mid-line wraps like text; a real `<button>` is an atomic inline box and pushed the quote onto its own lines. While a run continues after the first section, the line under the last section says the next one follows (`more`), never the empty state's 'first section' line. The scroller pads the side where the sprite's figure sits (from `onFigure`, re-measured on resize), so no line runs under it; the text never narrows below 360px for it. With no reading, `ReadingStart` shows the typewriter, the line and 「写解读」; the typewriter types only while the requested reading has no section.
- `reading-ask.ts`: pure helpers. The question message format lives in `MODEL_TEXT.askReading` (`> quote` lines, `— 解读《item》· N. section`, a blank line, the person's words) and is parsed back by `READING_PLACE`; the service reads the same format with its own parser (`mastra-service/src/studio/reading-question.ts`, so sediment counts only the words), bound by `tests/reading.test.ts`; footprints are rebuilt from conversation messages, never stored. `readingSignal` is the ids of completed reading_write calls; `answered` says an idle conversation already replied to a request; `sendErrorText` maps a native send refusal through the error catalog.
- `useReading.ts`: `useReading` loads the topic's reading list and the shown reading (the picked material, else the newest) by ETag, refreshed by the reading signal plus a 5s fallback only while the topic runs (the board's rule); the list is keyed by the topic it was read for, so a topic switch never asks the new topic for the old topic's reading; a material missing from the list has no reading yet and is not fetched (the list's next refresh brings it), so a write request costs no 404; `useTopicAsks` gathers questions from every conversation of the topic: the open one live, the others from stored history keyed by their last message.
- `reading.css`: the Reading view's own sheet: the in-view scroller (the page never scrolls), the column, the quote line, chips, footprints, the window (solid surface), the material row action and the empty view's start block.
- `Sprite.tsx`: reads the full view of the conversation feed StudioApp lends it (it never opens its own) and owns one useSpriteExpression snapshot shared by both renderers. It reports its figure's viewport box (`onFigure`, null when docked) so the Reading view keeps text clear of it. Body/avatar mount changes during opening and closing never reset the expression clock. Existing 60×92 hitbox, anchors, drag, dock, unread handling and session controls remain here.
- `SpriteFigure.tsx`: pure A04 renderer; compact uses the supplied 2x/3x sources and desktop uses 452px Retina derivatives. Both sizes share five faces, one persistent neutral silhouette and fixed facial overlays; PNG masters are never imported.
- `SpriteFigure.css`: float/think/wait/speak motion on one wrapper, invariant neutral shadow, glow, face masks and opacity cross-fades. Hidden documents pause motion; reduced motion removes animation and transitions for both renderers.
- `SpriteFace.tsx`: pure circular A04 avatar renderer and head source map; consumes the exact snapshot used by the body. Its facial overlays leave the neutral hair/outline invariant.
- `sprite-face.ts`: state mapping, single-timer FaceDriver and useSpriteExpression lifecycle. Idle blinks after 4–7s for 120ms; speech alternates after 180–260ms. Hidden/reduced owners schedule no expression timers; unmount cancels the owner.
- `objects/`: the isometric objects (kit, box, cabinet, typewriter, easel) and their one React host; see `objects/CLAUDE.md`. They are decoration over empty space: never focused, never in the way of a control.
- `sprite-desktop/`: retained native entry/bridge and local preference; centrally disabled, with no settings entry or projection. Its own window uses the same A04 renderer and pauses its owner while invisible.
- `sprite-place.ts`: pure nearest-edge anchors, viewport clamping, legacy migration, 4px drag threshold, 16px keyboard moves and open/close/reduced keyframes. Resizing changes display clamping, never the stored anchor.
- `useSpriteMove.ts`: pointer capture and drag/click separation, ref-only motion during drag, anchor persistence on release, and reversible Web Animations. During transitions inert shields the outgoing form; no duplicate animation layer is created.
- `useSpeaking.ts`: current native assistant text projects through stream-pulse; collapsing keeps text updates and opening reuses the subscription.
- `studio.css`: token-based shell geometry, typography, controls, pane/reader layout, view navigation, materials and sprite interaction chrome, and where the box and the cabinet stand. Shared character rendering lives in SpriteFigure.css.

Language: every visible string here comes from `useT().studio` (or `t()` outside components); service errors arrive already in the UI language. The objects' drawn labels come from `studio.objects`. No literal UI text in this folder; `npm run check:i18n` enforces it.

Subscription flow: StudioApp's useSessionFeed → Sprite reads the full view (useFeedView: Conversation, speaking); StudioApp selects the reading_write signal, the running flag and live questions (useFeedSelect) for the Reading view; both at most once per frame; no second stream.

Expression flow: session → spriteState → one useSpriteExpression → SpriteFigure + SpriteFace. Position and window lifecycle never flow back from the art layer.
